# Changelog — v1.0.0 (2026-10-17)

## Changes — 2026-10-21
- Fixed the failure notifier so a hard failure always emails, even when the failure broke the database. `run.py --failure-hook` is the service's `ExecStopPost` - the last chance to say the OCR is down - but `main()` called `database()` before reaching that branch, so a full disk or a corrupt `state.sqlite3` raised inside the notifier and the owner heard nothing at all, which is precisely the failure that most needs the email. The hook now runs before anything touches the database. Verified by pointing `STATE` under a regular file so `database()` genuinely cannot open, then confirming the hook still mails. Both requested cases were verified end to end rather than read: a stop by the owner (`systemctl stop` -> `SIGINT` -> `Stopped`) sends one `finished` mail reading "OCR stopped by owner/system: ... Unfinished inputs retained." and exits 0, so systemd reports `success` and the hook correctly stays silent instead of doubling it; and a hard failure emails - `SERVICE_RESULT` of `signal`/`core-dump`/`timeout`/`exit-code`/`start-limit-hit` each produce a `failed` mail naming the result and exit status, while `success` and an unset result stay silent. A Python-level exception mails the exception type and message from `main()` and then re-raises, so `ExecStopPost` mails a second, terser one: **two emails per Python-level hard failure, one per signal-level kill** (SIGKILL, OOM, segfault never reach the Python handler). Left as-is deliberately - a duplicated failure notice is far cheaper than a suppressed one during a month of unattended running, and the two carry different detail. Not verified: real systemd, so the actual `SERVICE_RESULT` strings and whether `ExecStopPost` runs when `ExecStartPre` fails are taken from systemd's documented behaviour, not observed here.

- Made the reminder timer hourly instead of every minute. `scraper-ocr-reminder.timer` had `OnUnitInactiveSec=1min` with `AccuracySec=10s`, so `run.py --remind` was invoked 1,440 times a day - about 43,200 times over the month the OCR is meant to run unattended - each one opening `state.sqlite3` to reach a decision the code was already refusing to act on more than once an hour. Now `OnUnitInactiveSec=1h` with `AccuracySec=1min`, which matches the `>= 3600` gate in `reminders()` instead of polling 60x per gated mail; 10s precision on an hourly timer buys nothing and only stops systemd coalescing the wakeup with other timers. `OnBootSec=2min` is kept, since it fires once per boot rather than recurring, so a restart does not wait an hour to be noticed. The 3600 s gate in `reminders()` stays and is what actually enforces one mail an hour: the OCR loop also calls `reminders()` after every book, so without the gate a busy queue would mail per book regardless of the timer interval. Re-ran the reminder suite unchanged - 19 retained failures still produce no mail and no latch, the 20th still produces exactly one, five further calls inside the hour still produce nothing, backdating `last_reminder` by 3601 s still produces a second, and clearing every retained failure still drops the latch without an extra mail. The rendered unit was checked rather than assumed. Systemd itself was not exercised: this sandbox has no systemd, so the timer's actual firing cadence is unverified here.

- Made this branch the source of truth for the OCR by porting it in from `main`: `ocr.py` (the `uv run ocr.py` installer), `deploy/continuous-ocr/{install.py,run.py,worker.mjs}`, the whole `ocr_runtime/` namespace (35 files, 27 MB, dominated by `model/mya.traineddata` at 24.7 MB) and `OCR-INSTALL.md`. `worker.mjs` imports eleven modules from `../../ocr_runtime/Praser/parser/`, so the runtime is not optional - the OCR cannot run without it. `main` tracks those files as ordinary git blobs rather than LFS, so porting them the same way follows the existing convention. Deliberately NOT ported: `graph/` (dead - only referenced in comments as "the tree builder is not shipped"), `OCR-MANIFEST.json` and both copies of `OCR-VERIFICATION.md` (point-in-time audit records whose whole claim is that the existing scraper modules stayed byte-identical, which the path-drift fix makes false), and the general docs this branch already consolidated into `todo.md` on 2026-10-20. `ocr.py` was checked against this branch before porting: all six modules it requires exist here, and it gates only on their presence, not on manifest hashes. `ocr_runtime/Praser/parser/package-lock.json` is tracked so the `npm ci` that `ocr.py` runs stays reproducible; verified no ported file is swallowed by `.gitignore`, which would have silently broken that.
- Switched the OCR to the SINGLE parquet. `commit_dataset` wrote one file per book to `pdfs/parquet/ocr/<sha256(source)>.parquet`; it now appends one row to `pdfs/parquet/books.parquet` through `text_collect.write_parquet_row`, the same writer and the same file the scraper's own convertable-book path uses. So the whole collection is one table with the existing four columns `author | book | text | segmented`, and `hfinit.py` pushes one file. This also removes the `ocr/` sub-folder the collection never needed, removes the `batch-<key>` staging directory (so there is nothing left behind to clean up), and removes the cross-device move entirely: `write_parquet_row` writes its dot-temp inside `pdfs/parquet/` and renames within that same directory, so the `os.replace` can never hit `EXDEV` if `pdfs/` turns out to be a separate mount from `scan/`. That hazard is now gone rather than worked around, and the per-book schema/row-count assertion went with the per-book file.
- Made the shared parquet collision-safe. The pipeline keys rows by filename minus `.pdf`, but the OCR walks the hosting directories recursively, so two different sources can share a basename - and `write_parquet_row` replaces the row of an existing key, which would have silently destroyed one book. `OCR-INSTALL.md` had explicitly promised "Equal basenames in different directories cannot collide", a guarantee the per-book `<hash>.parquet` naming provided and a single basename-keyed file does not. A new `book_key` gives it back: the basename is used when no other source holds it, otherwise `<name>-<first 8 hex of sha256(source)>`. The key is persisted in a new `books.book_key` column, added by a `pragma table_info` migration so an existing `state.sqlite3` keeps working, which also makes a retry reuse its own key and replace its own row instead of appending a duplicate.
- Serialised appends across PROCESSES. `write_parquet_row` guarded its read-modify-write with a `threading.Lock`, which cannot see another process - and one cumulative parquet now has two writers in two processes, `save_remote.push_file` and the OCR service. Two overlapping cycles would each start from the same table and the slower one would drop the other's row. Added an `fcntl.flock` on `.books.parquet.lock` beside the file, held around the whole read-modify-write inside the existing threading lock. Verified with two real subprocesses appending 12 rows each: 24 rows, none lost, every key present.
- Fixed the failure that stopped the whole service. `commit_dataset` was called bare, so anything past a `BookError` - segmentation exiting non-zero, an empty segmentation, the writer returning None - propagated out of `run()`. With `Restart=no` in the unit the service stayed down, and because the row was left in `ocr`/`segmenting` the query `status not in ('success','failed','removed')` re-selected it forever, so every book sorted after it was never reached and `reminders()`, which reads only `status='failed'`, never named it in an email. It is now wrapped: mark that one book `failed` with `commit: <reason>`, print `[commit-failed]`, run `reminders()`, continue. `Stopped` is a `BaseException`, so SIGTERM still propagates and shutdown is unaffected. The trade-off, restated: a transient commit failure now permanently marks the book failed instead of retrying at next start, which matches the existing `BookError` design and "Failed PDFs are not retried".
- Restart now reconciles by ROW instead of by per-book file, and self-heals. The check `Path(row['parquet']).is_file()` is meaningless when every row names the same cumulative file, so it reads the `book` column of `books.parquet` once and confirms each source marked success still has its row. A row that is absent - a `state.sqlite3` left over from the older per-book `ocr/<hash>.parquet` output - is re-queued to `pending` with a `[migrate]` journal line and re-OCR'd once, rather than raising `Committed Parquet missing` and bricking the service on every start. A second restart is a no-op.
- Gave the OCR service its `.env`. `run.py` imports `save_remote` and `mailer`, which read the repo-root `.env`, but the generated systemd units set only `Environment=PATH=` and `Environment=PYTHONUNBUFFERED=1`, so the service never saw the file an interactive run relies on. Added `EnvironmentFile=-<repo root>/.env` to the shared block, with the leading `-` so a missing `.env` is not fatal when the environment supplies the values instead. Rendered the actual f-string to check the output: absolute path, positioned before `StandardOutput`, and `%` in ROOT escaped to `%%` so systemd does not mis-parse the unit.
- Rewrote the parts of `OCR-INSTALL.md` that described the old layout: the per-book `pdfs/parquet/ocr/<hash>.parquet` output, the backup pairing, the restart presence check, the collision guarantee (now explained as the `book_key` rule), the cross-process lock, the `EnvironmentFile=` wiring with a pointer to `.env.example`, and the stale overlay-ZIP framing and `OCR-MANIFEST.json`/`OCR-VERIFICATION.md` references.
- PRESERVED the reminder rule exactly as asked - one email an hour once failed books reach 20 - and verified it rather than assuming it. `reminders()` counts only failures whose local PDF is still retained, marking the rest `removed`; below 20 and unlatched it returns silently; crossing 20 sets `reminder_latched`; then `time.time() - last_reminder >= 3600` gates delivery to one mail an hour, reserved before sending so the 1-minute timer and the main loop cannot double-send. - Added `hfinit.py` and deleted `hf-upload.sh`, which it replaces. With no argument it only logs in: it reads the `HG_TOKEN` access token (the one named `hg_full`) or prompts for it, stores it in the Hub cache with `huggingface_hub.login`, and confirms the identity with `whoami`. With a cwd-relative file or folder argument it pushes every `*.parquet` directly inside that folder (not recursive, and dot-files are skipped so the `.books.parquet.tmp` half-writes left by `text_collect.py` are ignored) into ONE hardcoded private dataset repo, `datasets/htetmyetflam3/scraper` - the user name and repo name are two obvious lines at the top of the file - created on first run. There is deliberately no repo listing or repo picker: one repo holds every dataset, and separate datasets inside it are separate Hub configs, which is what gets its own dropdown and viewer URL. Each file's name is compared against the repo's existing file list; a name already present is UPDATED in place and a new name is ADDED as a new dataset file, and every file in a run goes into a single commit through `create_commit`/`CommitOperationAdd` because the Hub allows only about 320 commit creations per hour. It needs `pyarrow>=21`; `pyproject.toml` still says `>=17`, and the flag fails loudly with the reason rather than silently uploading the un-optimised original if the installed PyArrow is older. The first `--cdc` run costs one full re-upload because every chunk boundary moves at once. The rewrite is checked to preserve the row count before it is uploaded.

- Added `vps.py`, a one-shot `ssh hostingervps` wrapper for the local container: `uv run vps.py --upload LOCAL REMOTE_DIR` and `uv run vps.py --download REMOTE LOCAL_DIR`, where the flag order is the only difference between the two directions. The local side is relative to the cwd; the remote side resolves against the VPS account home, read once over ssh with `echo $HOME`, so a quoted `~/scraper/...` can never expand to the local home. A path ending in `/` (or an existing directory) transfers every file inside it and skips sub-directories, transfers stream through `cat` in binary so a 300 KB random-byte file round-trips byte-identical, and a failed download removes its own empty destination file. It reuses the hardcoded `~/.ssh/mylinux` key pinned with `IdentitiesOnly=yes` from `vps-pull.sh`, deletes nothing on either box, and is deliberately simple - no resume, retry waits or sha256 pass, which `vps-pull.sh` still covers for the large Parquet collection.
- Added two operator shell scripts for moving the VPS Parquet to Hugging Face, written in `gitinit.sh` style (`set -euo pipefail`, inline `DEFAULT_*` constants at the top, `[OK]`/`[INFO]`/`[ERROR]` prefixes, loud failure instead of retry logic). `hf-upload.sh` pushes Parquet to a Hub dataset with the `HG_TOKEN` access token (the token named `hg_full`, read from the environment or the repo-root `.env`, never passed as `--token` so it stays out of `ps`): with no argument it uploads the hardcoded `pdfs/parquet/books.parquet` on the VPS, with a cwd-relative path or folder it uploads that instead, and the repo is created on first run as `htetmyetflam3/<parquet-name>`, private by default. `vps-pull.sh` downloads Parquet from the VPS over plain `ssh` in BatchMode through this box's `hostingervps` alias for HostName, Port and User, with the private key hardcoded as `DEFAULT_KEY="${HOME}/.ssh/mylinux"` (gitinit.sh style) and pinned with `IdentitiesOnly=yes`, so only that key is ever offered to the VPS and never a general key used for other hosts; it lists `--all` remote `*.parquet` while skipping dot-temps, resumes a half-finished download with `tail -c +N`, and renames its `.name.tmp` into place only after the local sha256 equals the VPS sha256. Neither script deletes anything on either box; the only file `vps-pull.sh` removes is its own unverified dot-temp.
- `hf-upload.sh` authenticates with the token rather than the `ssh/hf` key: the Hub requires a token to create a private repo and to store Parquet through LFS, so an SSH key alone is not enough on this path. Large Parquet needs no local `git-lfs` - `hf upload` streams it and a rerun resumes an interrupted upload.
- Added `huggingface_hub>=1.0` to `pyproject.toml` so `uv sync` provides the `hf` CLI that `hf-upload.sh` calls; the script falls back to `huggingface-cli` and then to `uv run hf`.
